Today we’re introducing Devin Review 2.0, which makes Devin Review the default tool for PR review when working with Devin.
Since August, we’ve cut the cost of reviewing a PR by 82%. A typical review now costs just $0.25-$0.75, making Devin Review cheap and effective enough to run on every PR.
On average across our customers, each bug that gets fixed costs about $2.25.
In this post, we first discuss why review matters more today than ever before. Then we dig deeper into Devin Review’s new cost profile, explore how Devin Review works with Devin, and introduce its latest improvements.
Code review is the bottleneck
The throughput of PRs is increasing, but our capacity for manual code review is not. Code review—the step immediately after PR creation—has become the new bottleneck of the SDLC.
One way to overcome this problem is to stop reviewing PRs or review fewer PRs. However, while this brings short term gains in throughput, it has long term costs in customer-facing bugs and code quality.
A better way to overcome this problem is to use agents to assist with review. Devin Review finds bugs automatically to make all PRs safer. It also produces a guided tour of the PR, so that the human review is faster and has more context.
5x cheaper since August
Since August, the cost of a Devin Review per PR has dropped by 82%. These savings came from a better mix of models across Devin Review and from harness optimizations.
Quality did not suffer. After the cost cuts, Devin Review found more bugs per PR, up from 1.22 to 1.32 on average.
Automatically review every PR
You can run Devin Review on individual PRs with a /devin review comment in GitHub or GitLab. You can also start one from the Devin Review page in Devin Cloud or Devin Desktop.
You can also choose to automatically run Devin Review on your PRs once they are ready for review. Much like CI, this ensures that fewer bugs get merged into your codebase. And this makes it so that when your developers open a fresh PR, there is a completed review with feedback waiting for them.
Devin Review supports using fine-grained rules to decide when a PR should be reviewed. You can choose to run Devin Review on draft PRs; or filter by file paths, branches, labels, and more. Our customers use these rules to minimize their spend by excluding low-value PRs.
Incremental PR reviews
When run again on the same PR, Devin Review now incrementally reviews only the parts of the PR that have changed. This applies by default to every PR. This has two benefits:
- New findings are focused on the latest changes, reducing noise.
- Costs are greatly reduced, as each push is smaller than the whole PR.
About 80% of PRs cost less than a dollar to review, including all pushes. Devin Review also has a configurable per-PR spend limit, so a runaway PR can’t run up the bill.
Devin Review’s automatic review rules can be set to run on every push. This allows Devin Review to find new bugs as the PR evolves and to refresh the guided tour. One-off reviews are helpful, but miss a large part of the PR lifecycle.
Fix bugs faster with Devin
Devin Review can review PRs from all sources, but it works best with Devin.
When you use them together, Devin investigates each finding and decides whether to fix it, dismiss it, or escalate it to you. By the time you return to the session, the only things left are the bugs and decisions that need your attention.
We have also made Devin Review 1.5x faster since August, with a median latency of 94 seconds, down from 139 seconds.
Make Devin Review work for you
We’re also introducing two features that give you more control over how Devin Review runs and what it looks for.
Effort levels
By default, Devin Review is tuned to be cost efficient. But in some parts of your codebase, such as billing or security-sensitive code, a missed bug costs far more than a review.
For those areas, we’ve added Devin Review Ultra, an effort level that runs a more thorough review at a higher cost.
Custom reviewers
By default, Devin Review looks for bugs. But many teams also have specialized checks they want to run on every PR, which look very different from a bug-finding pass.
Custom Reviewers, now in beta, let you turn those checks into reviewers that run inside Devin Review, using your own instructions. Internally, we run custom reviewers to enforce backend security practices, safe DB migrations, performant SQL queries, and accessible UI components.
Each custom reviewer can have its own automatic review rules. Its findings appear in your Devin Review results and flow into Devin’s automatic fixing, and it follows the same cost controls as the rest of Devin Review.
