For the last few weeks I&#8217;ve used Claude Mods to mold Claude Code to my AI engineering workflow. Claude Code is great out of the box, but every engineering workflow is different. Claude Mods let you make Claude Code yours, in the way you want to pay attention. The &#8220;paying attention&#8221; part is now the most important thing. In a recent Latent Space post, The Evolution of the Agent Harness , I argued that as models absorb more of the harness into their weights, the part that&#8217;s left faces the human. It becomes the Attention Interface : the layer that decides when the agent interrupts you, what it shows you, and which decisions it needs you to make. Claude Mods are an early version of the Attention Interface, and one you can shape yourself. Here&#8217;s my bet: ultimately, the harness becomes a platform that other companies build on , with models as the engine. Just as the browser became a platform for web apps, the harness could become a platform for the interfaces between people and agents. Claude Mods: What is it? A mod is a Claude Code plugin that consists of TypeScript or JavaScript functions that run inside Claude Code. These functions customize the behavior and appearance of the interface in the CLI and Desktop. Mods respond to events , like a prompt, tool call or interface render. They can observe the event, modify how it&#8217;s rendered, and handle it in place of the default behavior. Claude Mods are middleware for the agent harness . They inject code that changes Claude Code&#8217;s execution and rendering flow, changing how the application behaves at runtime. Claude Mods let the human and the agent build the human-facing part of the harness together. You can now work with Claude to design how Claude works with you. That is the essence of the &#8220;Attention Interface.&#8221; The harness reversal The agent harness started as an interface between the agent and the machine it runs on. It lets you prompt the agent and the agent then sends commands, edits files and calls tools. Now it&#8217;s gradually becoming a way for the agent to interface with the human. Claude Mods let you reverse the direction of the harness. Rather than the harness pointing from the agent to the machine, you point it from the agent to the human operator, and the harness becomes a way to interface with human attention. Claude Mods make the human layer programmable, by the human who uses Claude. Claude can also build mods for you. Claude Code has a built-in skill that teaches it how to build mods, so you can ask for the mod you want in plain language and Claude will build it. Mods in practice Some of Claude Code&#8217;s own features are already mods. Anthropic has shipped six of them built-in . You can see these by running /plugin and opening Installed , where they&#8217;re listed under Built-in: agents-md: loads AGENTS.md as project instructions. diff: takes over /diff and draws its pane. plugin-authoring: gives Claude the skill it uses to write mods for you. sec-default: guards what your organization manages from the mods a user installs. telemetry: sends the analytics records that Claude Code and its built-in mods log. you-should-know: a side agent that shows a note above the prompt when it finds something you might have missed. It&#8217;s the only one that&#8217;s off by default. Most of these work in the background, which is interesting because it means Anthropic is building parts of Claude Code as mods &#8212; even parts you may not notice. The one I&#8217;ve turned on myself is You Should Know . Here are the two mods I&#8217;ve found most useful in practice: one a built-in, and one I built myself. 1. You Should Know This is a native Claude Code plugin built by Anthropic. It runs a side-agent that observes the main agent while it works and flags important information you&#8217;re likely to miss. Think about it like: tool calls and decisions that have a material impact on the output, but aren&#8217;t necessarily easily visible because they&#8217;re buried in the agent trace. It comes built into Claude Code, but it&#8217;s off until you turn it on . Here&#8217;s a real example. I asked Claude Code to simplify the noisy UI text in one of my personal projects. The main agent trimmed the copy on the Compare screen, installed the new build and took before-and-after screenshots. Everything looked done. Then You Should Know flagged something for me. CompareView.swift, the file the agent was editing, already had uncommitted work in it &#8212; and so did about 45 other files. If I later discarded the demo edits, I&#8217;d throw away that earlier unfinished work too. Its suggestion was to commit or stash the earlier work first. In this case, the You Should Know mod saved me from discarding work unintentionally. 2. Next Steps Supervisor This mod only runs after a turn that edited files, ran commands or made 8 or more tool calls. In the screenshot below, you&#8217;ll see six different pieces of information flagged for your attention. Next Steps Supervisor then suggests a next step to take, as a clickable button which sends the instruction as a message to Claude Code. This mod is available as part of ModSmith &#8212; an open-source Claude Code plugin I built with several different built-in mods, as well as a template Claude can use to build new mods that work together. Attention Interfaces elsewhere Anthropic isn&#8217;t the only company that&#8217;s building an Attention Interface. Two recent products, one from OpenAI and one from Cursor, point in the same direction. Using the new ChatGPT Intelligent UI and Cursor&#8217;s PR Routing &amp; Approval as a frame of reference shows what&#8217;s unique about Claude Mods. ChatGPT&#8217;s Intelligent UI On October 7, OpenAI shipped GPT-6 inside ChatGPT alongside a new ChatGPT interface it calls Intelligent UI . Rather than answering only in text, ChatGPT now can generate an interface as it answers : charts, maps, checklists, forms, and small tools like a bill splitter or a savings calculator. All generated on the fly by the model as a type of generative UI . Source: OpenAI&#8217;s GPT-6 announcement In one of OpenAI&#8217;s examples, ChatGPT replies with multiple-choice follow-up questions to narrow down what you&#8217;re looking for. Think about it like: the model decides when it needs your judgment, then builds the interface for you to give it. That&#8217;s an Attention Interface. The agent designs how you interact with its response. But notice the difference between ChatGPT&#8217;s Intelligent UI and Claude Mods. For Intelligent UI, the model picks the interface, answer by answer, from a component library that OpenAI built. The one control mentioned at launch is turning the visuals down. Cursor&#8217;s PR Routing &amp; Approval Cursor is working on the same problem from the other end: not one person and one answer, but a team and a stream of pull requests , more and more of them written by agents. Someone has to decide which changes deserve the attention of the human-in-the-loop. PR Routing &amp; Approval makes that decision. It assigns reviewers based on code ownership and commit history, and it can auto-approve low-risk PRs. It weighs a risk score against a threshold you set, findings from Cursor&#8217;s Bugbot and Security reviewers, and policy files that live in the repo. One rule caught my attention during research. If a PR edits an approval policy, the agent won&#8217;t use the edited version to relax review on that same PR. It reads the policy from the base branch instead. That means an agent can&#8217;t change the rules to get its own PR approved. Cursor is also clear about the limits. Its docs say the feature &#8220;does not replace a full code review.&#8221; The point is to spend human review where it matters, not to remove it.
