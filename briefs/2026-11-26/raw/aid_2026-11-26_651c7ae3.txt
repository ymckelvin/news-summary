Takeaways from the conversation with Katelyn Here are 12 interesting learnings on how software engineering is changing inside of Anthropic: 1. Anthropic rewrote its API from Python to Rust in around five months. The API called &#8216;Messages API&#8217; serves all Claude tokens externally, as well as for Claude Code and Claude Desktop. This service does authentication, tokenization, billing, and safety checks, then calls the GPU stack to generate tokens. The service was a Python monolith and the team initially optimized Python, but found the performance overhead was still large. Eventually, they decided to rebuild it in Rust. It took a few engineers and a few months in total; all without anyone being expert in Rust! How the Claude API team had the Rust system shadow the Python one. See more details in the Anthropic engineering blog about the migration The Anthropic team published a longer walkthrough of the migration &#8211; check it out. 2. Hang on, why was the monolith written in Python in the first place? Back in 2023, Anthropic was still a research company when it decided to create an API, and the team that built it was small, with a large crossover to Research. It was the case that researchers worked mostly with Python, which made it very easy to integrate the API with inference and other infrastructure code. Similarly, OpenAI&#8217;s API was also written in Python &#8211; and later rewritten to Rust . Anthropic and OpenAI faced the same challenge with the Python monolith: the CPU footprint of the monolith started to become a growing problem. 3. The rewrite was done without Rust experts on the team or strict code reviews. A year earlier, the same team picked Go for their new services because it was a language that team members knew how to read and write. But by 2026, they felt that Claude was good enough at Rust, and Claude helped engineers learn more about Rust during the rewrite. The team did not do strict code reviews, but had the &#8220;unfair&#8221; advantage of the existing Python API being a perfect test harness. They set up the new Rust API to shadow the current API, and iterated until all responses were identical. Also, Katelyn estimates that engineers looked closely at only ~20% of the code generated: &#8220;As long as you can really boil something down to make it verifiable in some way, then you don&#8217;t have to look at every single line of Rust code that&#8217;s getting written.&#8221; 4. Anthropic has its own code review agent running at all times. The company has a Claude code review classifier running for all pull requests. It decides: Does it need a human review? For &#8220;mechanical&#8221; and low risk changes like an SDK version bump or using a newer model, Claude can decide there&#8217;s no human review needed. This is also the case for fixing flaky tests, in which case, another Claude does the review, then merges and deploys it. How many human reviews does it need? For changes that do need human reviews, Claude scores the risk and takes into account additional rules to decide how many human reviews are needed. Which team needs to do a review? Claude routes the PR to the right teams. 5. A Claude agent is paged before a human for API oncall. For months, a Claude agent has been shadowing the API oncall rotation of the API team for training. As the team have gained confidence that Claude can tell if an alert is &#8220;real&#8221; or &#8220;noise,&#8221; they now let this agent categorize an incoming alert first. The long-term goal is for Claude to handle actual incidents without waking up a human &#8211; but they&#8217;re not there yet. We cover more on how AI SRE startups are tackling the same challenge in our recent deepdive, AI SRE: what is it, how could it change on-call &#8211; and does it work? 6. Onboarding for new Anthropic engineers is &#8220;talk to Claude.&#8221; New joiners at tech companies used to have &#8220;onboarding buddies&#8221; and engineers who explained the architecture of systems to them, often by drawing boxes and diagrams. Not so at Anthropic, where Claude is connected to the codebase and internal systems, and engineers just ask it to explain how things work. Claude can even create interactive tutorials and visualizations. It&#8217;s pretty similar to how OpenAI engineers use Codex for onboarding, as covered in our podcast episode with Tibo Sottiaux . 7. One thing that hasn&#8217;t changed is the need for planning and alignment. Katelyn&#8217;s team interacts with Inference, Research, Safety, and App teams. When kicking off a project, a lot of time and effort is spent on getting everyone on the same page. Katelyn says that planning time has not changed much from &#8220;pre-AI&#8221;. The average engineer actually spends more time coordinating than on implementation! 8. Another thing that has not changed is two-pizza teams . Teams at Anthropic are still two-pizza teams of around 5-8 people. Katelyn says it&#8217;s because this is the right size for understanding a complex system and staffing an oncall rotation.
